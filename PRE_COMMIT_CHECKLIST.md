# Pre-Commit Verification Checklist

Use this checklist before every commit to ensure code quality and consistency.

---

## ✅ Code Quality

### Compilation & Build
- [ ] `npm run build` completes without errors
- [ ] No TypeScript errors (`tsc --noEmit`)
- [ ] No ESLint warnings/errors (`npm run lint`)

### Testing
- [ ] Existing tests pass (`npm test`)
- [ ] New features have tests
- [ ] Edge cases are covered

### Functionality
- [ ] Feature works as expected in browser
- [ ] No console errors in DevTools
- [ ] Mobile responsive (test at 375px, 768px, 1024px)
- [ ] Works in Chrome, Firefox, Safari

---

## 📝 Commit Message Quality

### Format Check
- [ ] Uses conventional commit format: `<type>(<scope>): <subject>`
- [ ] Type is correct: `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `chore`
- [ ] Scope is relevant: `agents`, `blockchain`, `nft`, `marketplace`, `ui`, etc.
- [ ] Subject is lowercase, imperative mood, no period
- [ ] Subject is under 72 characters

### Content Check
- [ ] **NO** "Generated by Spark" text
- [ ] **NO** auto-generated/generic messages
- [ ] Message clearly describes the change
- [ ] Includes "why" not just "what" (in body if needed)
- [ ] References issues if applicable (`Closes #123`)

### Examples of Good Messages
```
✅ feat(agents): add neural fusion breeding system
✅ fix(blockchain): resolve gas estimation edge case  
✅ docs(readme): update environment setup instructions
✅ refactor(components): reorganize agent components
✅ perf(analytics): optimize chart rendering performance
```

### Examples of Bad Messages (Avoid!)
```
❌ Generated by Spark
❌ update code
❌ fix bugs
❌ changes
❌ work in progress
❌ feat: added breeding feature (past tense)
```

## 🔒 Security & Best Practices

### Code Review
- [ ] No hardcoded secrets or API keys
- [ ] No console.log() statements (use proper logging)
- [ ] No commented-out code blocks
- [ ] No TODO comments without issue reference

### Environment Variables
- [ ] Sensitive config uses environment variables
- [ ] .env.example is updated if new vars added
- [ ] No .env file committed to repo

### Dependencies
- [ ] No unnecessary new dependencies added
- [ ] Used dependencies are from trusted sources
- [ ] Package versions are pinned or use safe ranges

---

## 🎨 Code Style & Formatting

### TypeScript
- [ ] All types are properly defined (no `any`)
- [ ] Interfaces/types are exported if reused
- [ ] Complex types are documented

### React
- [ ] Components use proper hooks (useState, useEffect, etc.)
- [ ] useKV used for persistent data (not localStorage)
- [ ] Functional updates for state that depends on previous value
  ```typescript
  ✅ setData((current) => [...current, newItem])
  ❌ setData([...data, newItem])  // Stale closure!
  ```

### Imports
- [ ] Imports are organized (React → 3rd party → Local)
- [ ] No unused imports
- [ ] Use `@/` alias for project imports

### Styling
- [ ] Use Tailwind classes (not inline styles)
- [ ] Follow existing color/spacing patterns
- [ ] Responsive design (mobile-first)

- [ ] Form inputs have labels
- [ ] Images have alt text
- [ ] Links describe destination

- [ ] All features accessible via keyboard

- [ ] Logical tab order

## 📄 Documentation

### Code Comments
- [ ] Complex logic is commented
- [ ] Public APIs are documented
- [ ] TODOs reference issue numbers

### File Changes
- [ ] README updated if user-facing features added
- [ ] CHANGELOG updated (if applicable)
- [ ] API documentation updated (if applicable)

---

## 🔄 Git Best Practices

### Branch Management
- [ ] Working on correct branch
- [ ] Branch is up to date with main
- [ ] No merge conflicts

### Commit Scope
- [ ] Commit is atomic (one logical change)
- [ ] Related changes are grouped
- [ ] Unrelated changes are in separate commits

### Review Before Push
- [ ] Review diff: `git diff --staged`
- [ ] Check changed files: `git status`
- [ ] Verify commit message: `git log -1`

## Quick Command Reference

```bash
# Check for errors
npm run build
npm run lint

# Run tests
npm test

# Review changes
git status
git diff
git diff --staged

# Commit with proper message
git commit -m "feat(scope): descriptive message"

# Amend last commit if needed
git commit --amend

# Check commit history
git log --oneline -5
```

## Common Issues & Solutions

### Issue: TypeScript errors after update
```bash
# Clear cache and reinstall
rm -rf node_modules package-lock.json
npm install
```

### Issue: Build fails but dev works
```bash
# Check for dynamic imports or env vars
npm run build
# Review error output carefully
```

### Issue: Tests fail locally
```bash
# Update test snapshots if UI changed
npm test -- -u
```

### Issue: Merge conflicts
```bash
# Update from main
git checkout main
git pull
git checkout your-branch
git rebase main
# Resolve conflicts
git rebase --continue
```

## Automated Checks (Future Enhancement)

Consider setting up:

```bash
# Install husky for git hooks
npm install -D husky

# Install commitlint
npm install -D @commitlint/cli @commitlint/config-conventional

# Install lint-staged
npm install -D lint-staged
```

**Example `.husky/pre-commit`**:
```bash
#!/bin/sh
npm run lint
npm test
```

**Example `.husky/commit-msg`**:
```bash
#!/bin/sh
npx commitlint --edit $1
```
