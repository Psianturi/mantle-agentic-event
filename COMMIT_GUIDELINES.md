# Git Commit Message Guidelines

## Overview

This document establishes the commit message standards for the MAEF project. Professional, clear commit messages improve collaboration, code review efficiency, and project history readability.

---

## Commit Message Format

### Structure

```
<type>(<scope>): <subject>

[optional body]

[optional footer]
```

### Rules

1. **Subject Line**
   - Maximum 72 characters
   - Start with lowercase
   - No period at the end
   - Use imperative mood ("add" not "added" or "adds")

2. **Type** (Required)
   - Must be one of the following:

   | Type | Description | Example |
   |------|-------------|---------|
   | `feat` | New feature | `feat(agents): add breeding cooldown system` |
   | `fix` | Bug fix | `fix(blockchain): resolve gas estimation error` |
   | `docs` | Documentation only | `docs(readme): update installation steps` |
   | `style` | Code style changes | `style(app): fix formatting and indentation` |
   | `refactor` | Code refactoring | `refactor(hooks): simplify useBlockchain logic` |
   | `perf` | Performance improvement | `perf(analytics): optimize chart rendering` |
   | `test` | Adding tests | `test(agents): add breeding logic tests` |
   | `chore` | Maintenance tasks | `chore(deps): update dependencies` |
   | `build` | Build system changes | `build(vite): update configuration` |
   | `ci` | CI/CD changes | `ci(github): add automated testing workflow` |

3. **Scope** (Optional but Recommended)
   - Indicates the part of codebase affected
   - Examples: `agents`, `blockchain`, `ui`, `marketplace`, `nft`, `ipfs`

4. **Subject** (Required)
   - Brief description of the change
   - What the change does, not what you did

5. **Body** (Optional)
   - Detailed explanation of the change
   - Wrap at 72 characters per line
   - Explain the "what" and "why", not the "how"

6. **Footer** (Optional)
   - Reference issues: `Closes #123`, `Fixes #456`
   - Breaking changes: `BREAKING CHANGE: description`

## Examples

### ✅ Good Examples

#### Simple Feature Addition
```
feat(agents): add neural fusion breeding system

Implement genetic inheritance algorithm that merges wisdom data
from two parent agents. Offspring inherit traits, knowledge, and
receive generation-based rarity bonuses.

Closes #234
```

#### Bug Fix
```
fix(blockchain): handle insufficient gas edge case

Add validation before transaction submission to prevent failed
transactions when user has insufficient gas balance. Display
clear error message with suggested top-up amount.

Fixes #567
```

#### Refactoring
```
refactor(components): reorganize agent components

Move agent-related components from root to /components/agent
directory for better code organization. Update all import paths
and maintain backward compatibility.
```

#### Documentation
```
docs(architecture): add blockchain integration guide

Create comprehensive guide explaining smart contract deployment,
IPFS metadata storage, and Mantle Network integration patterns
used throughout the application.
```

#### Dependency Updates
```
chore(deps): update react and react-dom to 19.2.6

Patch version update includes bug fixes for concurrent rendering
and improved error boundary handling. No breaking changes.
```

#### Performance Improvement
```
perf(analytics): optimize chart component rendering

Implement React.memo() for chart components and add useMemo()
for expensive calculations. Reduces re-renders by 70% during
agent activity updates.
```

#### Breaking Change
```
feat(api): redesign agent spawning API

Simplify agent creation by consolidating sub-agent configuration
into single initialization call. Reduces complexity and improves
performance.

BREAKING CHANGE: AgentFactory.spawn() now requires niche
parameter. Update all spawn calls to include niche selection.
```

---

### ❌ Bad Examples (Avoid These)

#### Too Vague
```
❌ update code
❌ fix bugs
❌ changes
❌ work in progress
```

#### No Type Prefix
```
❌ added breeding feature
❌ fixed the blockchain thing
```

#### Generated/Auto Messages
```
❌ Generated by Spark
❌ Auto commit
❌ Save work
❌ Update
```

#### Too Long Subject
```
❌ feat(agents): add comprehensive neural fusion breeding system with genetic inheritance, cooldown management, and rarity calculation
```

#### Past Tense
```
❌ feat(agents): added breeding feature
❌ fix(ui): fixed button styling
```

## Workflow Integration

### Pre-Commit Checklist

Before committing, ask yourself:

1. ✅ Does my commit message follow the format?
2. ✅ Is the type correct?
3. ✅ Is the scope relevant?
4. ✅ Does the subject clearly describe the change?
5. ✅ Have I removed any "Generated by Spark" or auto-generated text?
6. ✅ Is the message in imperative mood?

### Git Hooks (Optional)

Consider adding `commitlint` to enforce these standards:

```bash
npm install -D @commitlint/cli @commitlint/config-conventional
```

Create `.commitlintrc.json`:
```json
{
  "extends": ["@commitlint/config-conventional"],
  "rules": {
    "type-enum": [2, "always", [
      "feat", "fix", "docs", "style", "refactor",
      "perf", "test", "chore", "build", "ci"
    ]],
    "scope-enum": [2, "always", [
      "agents", "blockchain", "nft", "marketplace", "analytics",
      "ui", "terminal", "fusion", "wisdom", "wallet", "ipfs",
      "deps", "config", "docs"
    ]]
  }
}
```

## Multi-Change Commits

### When to Split

Split commits when changes are:
- ❌ Unrelated features
- ❌ Different bug fixes
- ❌ Refactoring + new feature

### When to Combine

Combine when changes are:
- ✅ Part of same feature
- ✅ Related bug fixes
- ✅ Tests + implementation

### Example: Multiple Related Changes

```
feat(agents): implement complete breeding lifecycle

- Add breeding dialog with parent selection UI
- Implement genetic inheritance algorithm
- Add cooldown timer and boost mechanism
- Create generation and lineage tracking
- Add breeding cost calculation
- Update agent cards with breeding status

Closes #123, #124, #125
```

## Additional Resources

### Semantic Versioning
- Major version: Breaking changes
- Minor version: New features (backward compatible)
- Patch version: Bug fixes

### Git Best Practices
1. Commit early and often
2. Each commit should be atomic (one logical change)
3. Write commit message for future developers
4. Reference issues when applicable
5. Use branches for features

### Useful Git Commands

```bash
# Edit last commit message
git commit --amend

# Interactive rebase to clean up commits
git rebase -i HEAD~5

# Show commit history with formatting
git log --oneline --graph --decorate
```
